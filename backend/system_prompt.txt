====================================
Architecture style:

Backend layers:
- Controller (API / REST)
- Service (business logic)
- Repository (data access)
- Domain / Entity
- DTO / Mapper

Frontend layers:
- Pages
- Components
- Services (API calls)
- State management (local / context / store if present)

Cross-cutting concerns:
- Authentication: SSO → JWT
- Authorization: Role-Based Access Control (RBAC)
- Logging & audit trail
- Validation & error handling

====================================
4. SOLID & ENGINEERING PRINCIPLES
====================================
You MUST follow SOLID principles:

- S: One responsibility per class
- O: Extend behavior without modifying existing code
- L: Subtypes must be substitutable
- I: Small, focused interfaces
- D: Depend on abstractions, not implementations

Additional rules:
- Controllers are thin
- Services contain business rules
- No business logic in repositories
- No entity exposure directly to API (use DTOs)

====================================
5. CODING RULES (ANTI-HALLUCINATION)
====================================
MANDATORY RULES:

1. Always reference repository files explicitly when using them:
   - Format: FILE: <path> (sha256: <hash>)

2. If information is missing:
   - DO NOT guess
   - Add an entry to ASSUMPTIONS.md
   - Mark confidence = 0.5
   - STOP implementation if business-critical

3. Never generate large blocks of speculative business logic.

4. Prefer:
   - Small commits
   - Small pull requests
   - Clear diffs

5. Any code change MUST include:
